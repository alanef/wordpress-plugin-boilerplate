# Deploy live: __PLUGIN_NAME__

Run by `/tk-deploy live`. Releases the version already set in the plugin header through
the two-tag Freemius pipeline (`"pipeline": "freemius-two-tag"` in `.tooling.json`):

tag here -> this repo's release.yml (checks, GitHub release, Freemius deploy as BETA,
generated free build pushed to `__FREE_REPO__`) -> tag `__FREE_REPO__` -> its SVN deploy
-> wordpress.org. Promotion to released in Freemius (plugin __FREEMIUS_ID__) is manual.

The free repo is generated by CI, so it is never kept or edited locally. Take a fresh clone
in a temp dir, only ever tag it, and remove it at the end:

```bash
F=$(mktemp -d)/free
GIT_TERMINAL_PROMPT=0 git clone -q git@github.com:__FREE_REPO__.git $F
```

<!-- include preconditions -->

Also, for this pipeline:

- If `origin/develop` exists it must be at HEAD too (the release is develop fast-forwarded
  to `__BRANCH__`): `git -C $P rev-parse origin/develop` = HEAD.
- The free repo has its own tag style (pin `"free_tag_prefix"` in `.tooling.json`; it defaults
  to `tag_prefix`). Only ever push `$FTAG` there:

  ```bash
  FTAG=__FREE_TAG_PREFIX__$V      # the free repo's tag
  ```
- On the free repo, tag `$FTAG` must not exist
  (`GIT_TERMINAL_PROMPT=0 git -C $F ls-remote --tags origin "refs/tags/$V" "refs/tags/v$V"` empty).
- The confirmation you ask for covers both tags; say so when asking.

## Tag and push

```bash
git -C $P tag $TAG && GIT_TERMINAL_PROMPT=0 git -C $P push origin $TAG
```

If the push fails, stop and report: the tag then exists only locally. Do not delete it,
retry or force; tell the user.

## Watch release.yml

```bash
gh run list -R __REPO__ --workflow release.yml --limit 5 --json databaseId,headBranch,status
gh run watch <id> -R __REPO__ --exit-status     # the run whose headBranch is $TAG
```

Run the watch in the background and wait for completion. Every job must succeed: quality
checks, tag/version guard, GitHub release, Freemius deploy, push free version. On failure
show `gh run view <id> -R __REPO__ --log-failed` and stop.

## Confirm the free build landed

```bash
FB=$(git -C $F symbolic-ref --short refs/remotes/origin/HEAD | sed 's#^origin/##')
GIT_TERMINAL_PROMPT=0 git -C $F fetch origin
git -C $F show origin/$FB:__MAIN_FILE__ | grep -m1 -oP 'Version:\s*\K\S+'
git -C $F log -1 --format='%h %s' origin/$FB
```

The version must equal `$V`, and the newest free repo commit must be the CI sync for `$V`.

## Tag the free repo

```bash
git -C $F tag $FTAG origin/$FB && GIT_TERMINAL_PROMPT=0 git -C $F push origin $FTAG
```

This fires the SVN deploy workflow there. Same rule: a failed push is reported, never retried.

## Watch the SVN deploy

```bash
gh run list -R __FREE_REPO__ --limit 5 --json databaseId,headBranch,workflowName,status
gh run watch <id> -R __FREE_REPO__ --exit-status     # the run whose headBranch is $FTAG
curl -s https://plugins.svn.wordpress.org/__SVN_SLUG__/tags/ | grep -c ">$V/<"   # must be 1
```

The wordpress.org API will NOT show `$V` yet if release confirmation is on. That is
expected; see the manual steps.

## Tell the user what is still manual

Always end with these, explicitly:

1. **Confirm the release on wordpress.org.** Release confirmation holds `$V` until a
   committer approves it from the confirmation email or the plugin's release confirmation
   page. Until then the directory still serves `$PREV`.
2. **Release in Freemius.** release.yml deploys as beta, so `$V` is beta in the Freemius
   dashboard (plugin __FREEMIUS_ID__) until promoted to released. Paying customers do not
   get the update before that.
3. Any server side follow-ups recorded in the release notes.

Then report: both tags, release.yml run, SVN run, changelog result, YouTrack updates. Put any `CHANGELOG PAGE NOT UPDATED` line on its own, first.
